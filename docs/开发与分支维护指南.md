# 开发与分支维护指南

本文档面向项目维护者与开发者，包含环境搭建、编译打包、素材重制，以及 **`main` + `release` 双分支体系的原理与日常发版流程**。所有命令均在项目根目录下执行。

---

## 一、 本地开发环境搭建与编译

### 1. Windows（项目内置独立工具链）

```powershell
# 1) 首次克隆后安装工具链（自动下载 Qt 5.15.2 MinGW 与构建工具到 third_party/qt，约 1GB）
powershell -ExecutionPolicy Bypass -File .\scripts\install_tools.ps1

# 2) 日常改代码后编译打包（直接使用已有 PNG 素材，无需 ffmpeg）
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1 -SkipAssets

# 3) 完整重提视频素材并编译（修改了 media/ 视频时使用，需安装 ffmpeg 与 Python Pillow）
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1

# 4) 运行测试
.\dist\QtCatPet.exe
```

### 2. Linux

```bash
# 依赖：qt5-default / qtbase5-dev、qtbase5-private-dev、ffmpeg、python3-pil
SKIP_ASSETS=1 ./scripts/build.sh   # 仅编译代码（使用已有素材）
./scripts/build.sh                 # 重提视频素材并编译
./dist/QtCatPet
```

## 二、 素材维护工具脚本

| 场景 | 执行方式 | 说明 |
| :--- | :--- | :--- |
| 重提猫咪视频帧 | `powershell -ExecutionPolicy Bypass -File .\scripts\extract_assets.ps1` | 从 `media/静止1.mp4` 和 `media/旋转1.mp4` 裁剪抠除黑底，输出到 `resources/assets/` |

## 三、 仓库双分支体系（`main` + `release`）

远程仓库地址：`git@github.com:LiMengyangLMY/QtCat.git`

### 1. 双分支定位对比

| 分支名称 | 面向人群 | 分支类型 | 包含内容 | 排除内容 |
| :--- | :--- | :--- | :--- | :--- |
| **`main`** | 开发者 / 维护者 | 常规开发分支（保留完整提交历史） | `src/`、`resources/`、`scripts/`、`docs/`、`media/`、`DesktopPet.pro` | `build/`、`dist/`、`third_party/`、`*.zip`、`*.lnk` |
| **`release`** | 普通用户（下载即用） | **单提交孤儿分支（Orphan Branch）** | 纯净 `dist/`（含 `QtCatPet.exe` 与全部 Qt/MinGW DLL）、`启动桌宠.bat`、`创建桌面快捷方式.bat`、用户版 `README.md` | 源码、构建工具链，以及**维护者个人的 `dist/books/` 和 `dist/bookshelf.csv`** |

### 2. 双分支运作原理图

```
本地唯一工作目录 (始终停留在 main 分支，无需建两个文件夹，也无需 git checkout release)
 │
 ├─── 源码提交通道：git add / commit / push origin main
 │      └──► 增量推送到 GitHub [main 分支]（轻量源码历史）
 │
 └─── 发行打包通道：运行 scripts/publish_release_branch.ps1 -Push
        ├── 1) 在系统 %TEMP% 创建净室临时目录，复制 dist/ 并剔除 books/ 与 bookshelf.csv
        ├── 2) 自动写入相对路径脚本：启动桌宠.bat、创建桌面快捷方式.bat、用户版 README.md
        ├── 3) 通过临时索引 (GIT_INDEX_FILE) + git write-tree / commit-tree 生成无父节点的单提交
        ├── 4) 更新本地 refs/heads/release 并执行 git push --force -u origin release
        └── 5) 自动清理 %TEMP% 临时目录（主工作区零污染）
```

### 3. 三条维护核心原则（防踩坑）
1. **单目录免切换原则**：本地只保留这一个项目目录，日常始终停留在 `main` 分支开发与自用，**不要**在工作区执行 `git checkout release`（否则会把源码工作区切换成纯二进制目录）。
2. **个人隐私自动隔离**：你在本机 `dist/QtCatPet.exe` 中导入的所有小说（`dist/books/`）和阅读进度（`dist/bookshelf.csv`）都会被 `publish_release_branch.ps1` 自动过滤，绝不会泄露到 GitHub。
3. **仓库体积零膨胀**：`release` 采用孤儿单提交覆盖更新，远端永远只保存最新一版约 60MB 的运行库，不会因多次发版累积成几百 MB 的历史包袱。

## 四、 日常版本更新与推送标准流程（SOP）

每次完成功能修改或 Bug 修复后，按顺序执行以下 3 步即可同步更新两个分支：

```powershell
# 第一步：关闭正在运行的 QtCatPet.exe，重新编译更新 dist\QtCatPet.exe
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1 -SkipAssets

# 第二步：提交源码并推送到 main 分支
git add .
git commit -m "feat: 简要描述本次更新内容"
git push origin main

# 第三步：一键重新生成 release 孤儿分支并覆盖推送到 GitHub
powershell -ExecutionPolicy Bypass -File .\scripts\publish_release_branch.ps1 -Push
```

## 五、 常见问题排查

1. **运行 `.ps1` 报错“在此系统上禁止运行脚本”**
   - 原因：Windows PowerShell 默认执行策略限制。
   - 解决：使用 `powershell -ExecutionPolicy Bypass -File .\scripts\xxx.ps1` 方式调用即可。
2. **编译复制 `QtCatPet.exe` 时报“文件正由另一进程使用”**
   - 原因：桌宠当前正在后台运行，锁住了 `dist\QtCatPet.exe`。
   - 解决：右键小猫点击“❌ 退出”（或执行 `taskkill /F /IM QtCatPet.exe`）后再运行构建脚本。
3. **`git push` 连接 GitHub 超时或卡住**
   - 原因：Git 自带的 MSYS `ssh.exe` 未读取系统 OpenSSH 密钥。
   - 解决：将仓库 SSH 客户端指向系统自带 OpenSSH：
     ```powershell
     git config core.sshCommand "C:/Windows/System32/OpenSSH/ssh.exe"
     ```
